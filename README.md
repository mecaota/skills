# skills
いい感じになったスキルをここに置いておく

## 収録スキル

| スキル | 概要 |
|---|---|
| retrospective | 作業後に、モデル・effort とサブエージェントの使い方が適切だったかを振り返り、教訓をログに記録する |
| japanese-review | 日本語で書いた文書を、Antigravity(gemini MCP)→ gemini-api → セルフレビューの順で校正する |
| orchestrator | メインセッションを自分では作業しない指揮塔(管理職)にして、サブセッションとサブエージェントに下請けに出す。どこまで任せるかをオプションで指定できる |

## インストール

Claude Code で次を実行します。

```
/plugin marketplace add mecaota/skills
/plugin install retrospective@mecaota-skills
/plugin install japanese-review@mecaota-skills
/plugin install orchestrator@mecaota-skills
```

## retrospective の使い方

次のように話しかけると起動します。

- 「振り返って」
- 「過去30日を振り返って」
- 「アーカイブ済セッションだけ振り返って」
- 「振り返ったらアーカイブして」

オプションは次の3つです。

| オプション | 既定 | 内容 |
|---|---|---|
| days | 0 | 0 は現在のセッションのみ。N(1以上)は直近 N 日間に活動があった全セッション |
| archived_only | オフ | オンにするとアーカイブ済セッションだけが対象 |
| auto_archive | オフ | オンにすると、振り返りとログへの記録が終わった後に対象のセッションをアーカイブする。days=0 なら現在のセッション、days が 1 以上なら振り返った各セッション |

`days` を 1 以上にする場合と、`archived_only`・`auto_archive` を使う場合は、Claude デスクトップアプリなどが提供するセッション管理ツール(`mcp__ccd_session_mgmt__*`)が必要です。使えない環境では、現在の会話だけを振り返り、アーカイブは行いません。

`auto_archive` の動作は次のとおりです。

- 振り返りが途中で失敗したときや、ログへの記録に失敗したときは、アーカイブしません。
- `archived_only` と組み合わせた場合、対象はすでにアーカイブ済なので何もしません。
- 作業中のセッションと、未コミットの変更があるセッションはアーカイブしません。アーカイブすると worktree も片付けられるためです。
- 現在のセッションは、報告を出し終えてから最後にアーカイブします。アーカイブすると会話はそこで終わります。設定の変更など、承認を待っている提案があるときは、現在のセッションはアーカイブしません。

## japanese-review の使い方

PRの Description、リリースノート、メモなど、日本語の文書を書き終えたときに起動します。「日本語をレビューして」「校正して」と話しかけても使えます。

- 外部レビュアーは `gemini` MCP の `ask`(Antigravity)、`gemini-api` CLI の順に試し、どちらも使えなければセルフレビューにします。
- 事前に、`gemini` MCP(Antigravity CLI `agy` を呼ぶもの)と `gemini-api` CLI の、少なくとも一方を使える状態にしておいてください。プラグインの依存では外部のMCPやCLIを宣言できないため、このプラグインは同梱も自動インストールもしません。起動時に使える手段を確認し、使えないものは飛ばします。
- 文法・表現の指摘は反映し、数値や挙動など事実を変える指摘は元の事実と照らして判断します。

## orchestrator の使い方

起動したあとのセッションは、自分では作業せず、指揮塔として仕事を下請けに出します。次のように話しかけると起動します。

- 「指揮塔になって、各タスクをサブセッションに分けて」
- 「全部サブエージェントに任せて」
- 「重い作業だけ委譲して」
- 「委譲をやめて」(解除)

オプションは次の3つです。既定は `scope=all`、`via=auto`、`session_per_task=true` で、メインはいっさい作業をしません。

| オプション | 値 | 内容 |
|---|---|---|
| scope | `all`(既定) | すべての作業を委譲する |
| | `heavy` | 重い作業だけ委譲する。1行レベルの修正や単発の読み取りはメインが行う |
| | `changes` | ブランチや PR に変更が残る作業だけ委譲する。調べ物はメインが行う |
| via | `auto`(既定) | 調べ物はサブエージェント、変更が残る作業はサブセッション、文脈を持つ既存セッションの続きはそのセッションへ伝達する |
| | `sessions` | サブセッションと既存セッションへの伝達だけを使う |
| | `agents` | サブエージェントだけで完結させる |
| session_per_task | `true`(既定) | 独立したタスクごとにサブセッションを1つ起動し、タスクの中の作業はそのサブセッションがサブエージェントに委譲する。`via=agents` のときやサブセッションの機能がない環境では `false` として扱う |
| | `false` | タスクごとの起動はせず、`via` の規則で使い分ける |

動作は次のとおりです。

- 完了通知は要約にすぎないため、本文と成果物を読み、重要な主張は確かめてからユーザーに伝えます。
- 検証は、作業者とは別の新しいエージェントに任せます。
- `session_per_task=true` では、同じタスクの続き(訂正、次の段階)は、新しく起動せずそのタスクのサブセッションへ伝えます。
- 公開・送信・削除・本番反映・commit・push・PR作成は、ユーザーの承認を取ってから任せます。PR のマージは担当に任せず、ユーザーの承認を得てからメインが行います。

サブセッションの機能(`start_session` など)は、Claude デスクトップアプリなどのセッション管理ツールがある環境で使えます。ない環境では、サブエージェントだけで進めます。

## 学習ログについて

- 振り返りで得た教訓は、あなたのマシン上の `~/.claude/retrospective/log.md` にだけ書き込みます。外部へは送信しません。
- `~/.claude/CLAUDE.md` やエージェント定義の編集は、変更内容を示したうえで、あなたが承認した場合にだけ行います。
